# Excel運用HTML化ツール

複数人・複数部署でExcelを使って個別にデータを集めている業務を、①項目構造の抽出→②入力フォーム配布→③データ集約→④閲覧ページの4段階で、単一HTML・ブラウザ完結のツールに置き換えます。様式構造を動的に読み取る設計のため、特定の業務に限定されません。

このREADMEは2部構成です。実際にツールを使う方は「ツール使用者向け」だけ読めば十分です。コードを触る方（人間・生成AIとも）は「開発者向け」も参照してください。

---

# ツール使用者向け

## 設計の前提

- **すべて単一HTMLファイル・ブラウザ完結・外部通信ゼロ**（Tier 0）。
- データの受け渡しは既存の組織内共有ドライブ・メール等、新規の通信経路を使いません。
- 特定ベンダー（クラウドサービス等）への依存もありません。

## 4ツールの使用順序

実際に使われる順に、誰が・何のために使うツールかをまとめます。①のみがリポジトリに実体として存在するファイルで、②③④は①・③が実行時に生成する成果物です（生成の仕組みは「開発者向け」参照）。

### ① Excelフォーム変換ツール（`index.html`）
**使う人：対象業務の管轄部署・事務局（フォームを設計する人）**

既存のExcel様式を読み込み、次の5ステップでフォームを設計します。

1. **STEP1 読み込み**：Excelファイルをアップロード
2. **STEP2 セルの設定**：各入力欄の型（テキスト／数値／金額／プルダウン）を確認・調整
3. **STEP3 データ構造確認**：項目名（データベース上の列名）を設定
4. **STEP4 項目の運用設定**：必須項目・2次入力画面表示項目・2次入力欄を設定
5. **STEP5 書き出す**：フォームのタイトルを設定し、1回のボタン操作で次の2ファイルを書き出す
   - `{タイトル}_入力フォーム.html` → ②へ
   - `{タイトル}_集約ツール.html` → ③へ

両ファイルとも、この時点で確定した構造だけから作られ、実データには一切依存しません。1回の書き出しで両方が同じ構造から生成されるため、②を配布した後に構造を調整しても、③が古いまま取り残されることがありません。

### ② 入力フォーム（`{タイトル}_入力フォーム.html`）
**使う人：各担当課の職員（1次入力者）／事務局の2次入力担当（2次入力者）**

①が書き出した、様式ごとに固有のフォームです。起動画面で2つのモードを選べます。

- **新規入力モード**（1次入力者向け）：1件分の内容を入力し、`{タイトル}_{識別項目...}_{日付}.json` を書き出す。既存の庁内経路（共有ドライブ・メール等）で事務局へ提出
- **2次以降入力モード**（事務局・2次入力者向け）：各課から集まった複数のJSONをまとめて読み込み、判定・コメント等の2次入力欄への記入、一覧表示・絞り込み・印刷を行い、更新したJSONを再度書き出す

### ③ 集約ツール（`{タイトル}_集約ツール.html`）
**使う人：事務局・取りまとめ部署**

①が書き出した集約用ツールです。各課から集まった最終JSONを全件まとめて読み込み、そのうち何を・どこまで閲覧させるかを設定（「閲覧設定」）した上で、閲覧ページと再利用できる集約データを書き出します。

- 閲覧設定：①一覧・詳細に表示する項目／②集計対象（数値・金額項目、単位付き）／③検索対象項目／④説明文・出典・データ最終更新日
- 書き出し（3種類）：
  - `{タイトル}_閲覧ページ.html` → ④へ
  - `{タイトル}_集約データ_{日付}.json`（内部保管用スナップショット）
  - `{タイトル}_集約データ_{日付}.csv`（Excel等での二次利用用。1件＝1行の表形式で、繰り返し行は数値・金額型なら合計、テキスト型なら「／」区切りで1セルにまとめる）

### ④ 閲覧ページ（`{タイトル}_閲覧ページ.html`）
**使う人：閲覧者**

③が書き出した、最終的にWeb公開される単一HTMLです。

- 一覧・検索画面：キーワード検索、列フィルタ、列表示切替、☑による絞り込み、データごとのメモ、絞り込み結果の集計表示、印刷
- 詳細画面：1件ごとの詳細表示、URLフラグメントによる直接リンク、絞り込み結果内の前へ／次へナビゲーション、単票印刷

# 開発者向け（人間・生成AI共通）

## ファイル構成と、それぞれがどのツールの実行中に動くか

②③④はリポジトリにファイルとして常設されているわけではなく、①・③の「書き出す」ボタンを押した時点でブラウザが生成します。そのため各`.js`/`.html`部品は、ビルド時に**入れ子状に埋め込まれて**います（`assemble.py`のdocstring参照）。

```
filler_template.html + core_logic.js + grid_render.js + filler_app.js
  → ②「入力フォーム」のHTML全文（テキストとして組み立てる）
  → このテキストをJS文字列としてbuilder_app.jsに埋め込む

viewer_template.html + core_logic.js + grid_render.js + viewer_app.js
  → ④「閲覧ページ」のHTML全文
  → このテキストをJS文字列としてaggregator_app.jsに埋め込む

aggregator_template.html + core_logic.js + grid_render.js
  + （④埋め込み済みの）aggregator_app.js
  → ③「集約ツール」のHTML全文
  → このテキストをJS文字列としてbuilder_app.jsに埋め込む

builder_template.html + vendor/xlsx.core.min.js + core_logic.js + grid_render.js
  + （②・③埋め込み済みの）builder_app.js
  → index.html（①。リポジトリ上の唯一の成果物）
```

このため、`.js`ファイルの中身は「そのファイルが対応するツールを実際に開いている間だけ」動きます。①`index.html`を開いている間、②③のコードはただの文字列としてページ内に存在しているだけで、実行はされません（②を開いた瞬間に初めて`filler_app.js`の中身が動き出す、という関係です）。

| ファイル | 役割 | 実際にコードが動くタイミング |
|---|---|---|
| `assemble.py` | ビルドスクリプト | ツールの利用時には一切関与しない。開発者が①を作り直す時に手元で`python assemble.py`を1回実行するだけ |
| `builder_template.html`<br>`builder_app.js` | ①フォームビルダーの骨格・ロジック | ①`index.html`を開いている間（STEP1〜5）ずっと動いている |
| `filler_template.html`<br>`filler_app.js` | ②入力フォームの骨格・ロジック | ②`{タイトル}_入力フォーム.html`を開いている間（新規入力／2次以降入力どちらのモードも）動いている。①を開いている間は埋め込み文字列として存在するだけで実行されない |
| `aggregator_template.html`<br>`aggregator_app.js` | ③集約ツールの骨格・ロジック | ③`{タイトル}_集約ツール.html`を開いている間動いている。①の中では埋め込み文字列として存在するだけ |
| `viewer_template.html`<br>`viewer_app.js` | ④閲覧ページの骨格・ロジック | ④`{タイトル}_閲覧ページ.html`を開いている間（一覧・検索画面／詳細画面とも）動いている。③の中では埋め込み文字列として存在するだけ |
| `core_logic.js` | Excel/JSON構造の解析（セクション分割・自動/手動グループ化・書き出し前チェック等） | ①②③④すべてで動く。同じ内容が4つのHTMLそれぞれに複製・埋め込みされている |
| `grid_render.js` | グリッド描画・貼り付け・印刷 | 同上、①②③④すべてで動く |
| `vendor/xlsx.core.min.js`（SheetJS） | Excelファイルの読み込み | ①のSTEP1（Excelアップロード）でのみ使われる。②③④はExcelを直接扱わないため含まれない |
| `index.html` | ビルド成果物 | 実際に配布・使用するのはこのファイル1つだけ |
| `test/` | 回帰テスト一式 | `npm test`で実行（ツール利用時には関与しない） |

## ビルド方法

部品ファイル（`*_template.html`・`*_app.js`・`core_logic.js`・`grid_render.js`）を編集した場合は、`index.html` を再生成してください。

```
python assemble.py
```

## テスト

```
npm test
```
